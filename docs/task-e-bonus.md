# Task E (bonus) — оберіть ОДИН шлях

## Шлях 3 — набір тестів на авторизацію

**Що зробили:** пройшли кожен `/api`-маршрут «не тим користувачем» через supertest на чистій `:memory:` базі (ті самі сіди: Оля=1, Тарас=2, нотатка Тараса **id=3**). Чужий caller — завжди інший `x-user-id`. Для `POST` окремо підсунули `user_id: 2` у JSON, ніби можна створити нотатку «за Тараса». Результати зведені в таблицю; крос-юзерні кейси також у `app/test/api.test.js`.

| Ендпоінт | Як чужий користувач | Очікувано | Фактично |
|---|---|---|---|
| `GET /api/notes` | Оля читає список | лише свої 2 нотатки; без «Приватна нотатка Тараса» і без `user_id` | **200**, 2 нотатки (`Список покупок`, `Ідеї для відпустки`); пароля від сейфа немає |
| `GET /api/notes/:id` | Оля → `GET /api/notes/3`; симетрично Тарас → `/api/notes/1` | 404, без тексту чужої нотатки | **404** `{ "error": "not found" }` в обидва боки (до C2 тут був **200** і `"пароль від сейфа: 1234"`) |
| `POST /api/notes` | Оля шле `{ title, user_id: 2 }` | власник = заголовок сесії, не поле з body; у Тараса список не росте | **201**, нотатка з’явилась у Олі; у Тараса як і було 1 запис |
| `DELETE /api/notes/:id` | Оля → `DELETE /api/notes/3` | 404; нотатка Тараса лишається | **404**; `GET` від Тараса далі length 1 |
| `PATCH /api/notes/:id/archive` | Оля → `PATCH /api/notes/3/archive` `{ archived: true }` | 404; `archived` у Тараса лишається false | **404**; у Тараса `archived: false` |
| *(контроль)* немає `x-user-id` | `GET /api/notes` без заголовка | 401 | **401** `{ "error": "not authenticated" }` |

**Що знайшли:** єдиний засіяний пропуск був на **читанні однієї нотатки** (`GET /api/notes/:id` шукав лише `WHERE id = ?`). Після C2 його немає. Інші маршрути вже різали дані по `req.userId` у SQL (`GET` списку, `DELETE`, `PATCH` архіву). `POST` ігнорує `user_id` у тілі — підміна власника через JSON не спрацьовує. Нового витоку, окрім уже закритого, матриця не показала.
